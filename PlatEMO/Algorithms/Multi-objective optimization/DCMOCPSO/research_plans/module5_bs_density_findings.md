# 模块 5：基站密度 bsPerKm2 调研记录

调研日期：2026-06-08

## 调研目标

本模块围绕 UAVPathPlanning 中的 `bsPerKm2` 展开调研，目标是为基站密度实验提供标准、城市实际部署和代码建模三方面依据。

当前实验脚本中的设置为：

```matlab
bsPerKm2List = [5, 10, 20, 30, 40];
baseProblemParameter = {20, 20, 5, -101.5, 0, 30, 2, 500, 10, 4};
```

其中 `baseProblemParameter{1}` 就是 `bsPerKm2`。

## 当前代码中的 bsPerKm2

`UAVPathPlanning.m` 中，`bsPerKm2` 的含义是“每平方公里的基站数量”。代码会先根据地图面积计算期望基站总数：

```matlab
map_area_km2 = map_area_m2 / 1e6;
totalBS = max(1, round(bsPerKm2 * map_area_km2));
numBS = max(1, ceil(totalBS / 2));
```

随后在选中的建筑物顶部部署基站：

```matlab
% 每个建筑物部署2个基站：一个在(x_min, y_min)，另一个在(x_max, y_max)
baseStations = zeros(numSelectedBuildings * 2, 3);
```

因此需要注意：输入的 `bsPerKm2` 是目标密度，实际生成的基站数量会受到地图面积、建筑物数量、四舍五入和“每个建筑物 2 个基站”的规则影响。整体上它仍然可以解释为每平方公里基站点位数量，但不应理解为严格等于每平方公里小区/扇区数量。

## 标准仿真依据：3GPP UMa/UMi

3GPP TR 38.901 中，典型城市蜂窝仿真部署包括：

- UMa：Urban Macro，宏基站，19 个 macro sites，3 sectors/site，ISD = 500 m。
- UMi：Urban Micro street canyon，微基站，19 个 micro sites，3 sectors/site，ISD = 200 m。
- UMa 还允许 ISD = 200-500 m 用于评估。

若按六边形站点网格近似换算站点密度：

```text
siteDensity = 2 / (sqrt(3) * ISD^2)
```

其中 ISD 用 km 表示。

| 3GPP 场景 | ISD | 站点密度约值 | 若按 3 sectors/site 计小区密度 | 对 bsPerKm2 的启发 |
|---|---:|---:|---:|---|
| UMa | 500 m | 4.62 sites/km^2 | 13.86 sectors/km^2 | `5` 可代表标准城市宏站密度。 |
| UMa dense / mixed | 300-400 m | 7.22-12.83 sites/km^2 | 21.65-38.49 sectors/km^2 | `10` 可代表较密集宏站或宏微混合低密部署。 |
| UMi | 200 m | 28.87 sites/km^2 | 86.60 sectors/km^2 | `30` 可代表标准城市微站/街区增强覆盖密度。 |

这说明当前 `bsPerKm2List = [5, 10, 20, 30, 40]` 有较好的标准解释空间：

- `5`：接近 UMa 宏站站点密度；
- `10`：较密宏站或宏微混合部署；
- `20`：介于宏站和微站之间的增强覆盖；
- `30`：接近 UMi 微站站点密度；
- `40`：高密城市、热点区域或 5G-A/小基站增强覆盖。

## 对当前 bsPerKm2List 的解释

当前实验：

```matlab
bsPerKm2List = [5, 10, 20, 30, 40];
```

建议解释为：

1. `5 stations/km^2`：稀疏宏站环境，接近 3GPP UMa 500 m ISD 的站点密度。
2. `10 stations/km^2`：常规城市宏站增强或宏微混合低密部署。
3. `20 stations/km^2`：中高密城市通信环境，介于 UMa 和 UMi 之间。
4. `30 stations/km^2`：高密微站/街区增强覆盖，接近 3GPP UMi 200 m ISD 的站点密度。
5. `40 stations/km^2`：超高密城市、园区、热点、低空经济重点区域或 5G-A 增强覆盖。

如果论文要强调“城市低空 UAV 巡检通信环境”，当前取值是合理的；它既覆盖标准仿真场景，也覆盖真实高密城市部署。

## 对指标变化的预期

随着 `bsPerKm2` 增大，指标可能出现以下变化：

- 平均信号强度：通常会上升。基站更密，UAV 到最近或最优基站的距离更短，LoS 候选更多。
- 覆盖率：通常会上升，但可能存在饱和。达到足够密度后，继续增加基站对覆盖率提升有限。
- 平均切换次数：通常会上升。基站越密，小区边界越多，候选基站更多，更容易发生切换。
- HV：不一定单调。如果 HV 同时偏好高信号、高覆盖和低切换，则中高密度可能最优；过低密度覆盖不足，过高密度可能因切换次数增加而拉低综合表现。

因此，`bsPerKm2` 很适合用于说明通信环境中“覆盖增益”和“切换开销”的权衡。

## 推荐实验解释

建议在论文中把当前五组写成：

```text
sparse macro, moderate urban, dense urban, micro-cell, ultra-dense hotspot
```

对应：

```matlab
bsPerKm2List = [5, 10, 20, 30, 40];
```

如果希望更严格贴合 3GPP 标准，也可以补充一组计算说明：

```text
UMa ISD = 500 m -> about 4.62 sites/km^2
UMi ISD = 200 m -> about 28.87 sites/km^2
```

这样 `5` 和 `30` 就分别有清晰的标准锚点，`10/20/40` 则作为中间和高密扩展组。

## 后续建议

后续模块 6 做参数耦合时，建议重点关注：

- `bsPerKm2 × velocity`：高速 UAV 在高密基站环境下可能产生更多切换。
- `bsPerKm2 × TTT`：高密基站下较大的 TTT 可能减少 ping-pong，但也可能造成切换滞后。
- `bsPerKm2 × altitudeCenter`：高度升高会增加 LoS 候选基站，基站密度影响可能被放大。

若只做单因素消融，当前 `[5, 10, 20, 30, 40]` 可以保留；若做真实城市场景组合，可考虑：

| 场景 | 推荐 bsPerKm2 |
|---|---:|
| 郊区/稀疏宏站巡检 | 5 |
| 普通城区 | 10 |
| 中高密城区 | 20 |
| 高密中心城区/深圳 2022 量级 | 30 |
| 超高密低空经济重点区域/深圳 2024 粗略量级 | 40 |
