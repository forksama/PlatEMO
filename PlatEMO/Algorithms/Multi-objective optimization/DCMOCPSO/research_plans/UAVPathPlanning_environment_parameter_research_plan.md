# UAVPathPlanning 环境参数调研计划

## 目标

围绕 UAVPathPlanning 中与算法优化无关、但与问题场景和环境设置有关的参数开展调研，形成有依据的实验参数设计方案。

重点参数包括：

- `bsPerKm2`：基站密度
- `velocity`：无人机速度
- `TTT`：Time-To-Trigger 切换触发时间
- `altitudeCenter`：预设飞行高度中心
- `altitudeBounds`：高度上下界范围

最终目标不是随意枚举参数值，而是形成：

```text
真实/典型场景 -> 环境约束 -> 参数范围 -> 推荐实验取值 -> 依据来源
```

## 调研来源范围

调研优先使用以下来源：

- 学术论文平台：IEEE Xplore、ScienceDirect、SpringerLink、ACM Digital Library、Wiley、MDPI、arXiv、中国知网、万方、维普等
- 政府官方网站：民航局、工信部、地方低空经济/无人机监管相关官网、地方政务公开平台等
- 标准与规范制定平台：3GPP、ITU、ETSI、IEEE Standards、国家标准全文公开系统、行业标准信息服务平台等
- 产业与白皮书资料：运营商研究院、通信设备厂商白皮书、低空经济/无人机产业报告等

调研结论需要记录来源，不直接使用无来源的经验值。

## 模块 1：应用场景背景调研

先确定无人机巡航/低空通信优化对应哪些真实应用场景，再反推参数设置。

重点调研：

- 城市低空巡检：北京、上海、深圳、广州、杭州等城市案例
- 电力巡检、河道巡检、交通巡查、园区巡逻、应急通信、物流航线等
- 城市低空经济、无人机航线、低空智联网相关试点
- 场景环境类型：城市核心区、普通城区、郊区、园区、河道、山区边缘等

建议输出表：

```text
城市/区域 | 场景 | 飞行高度 | 速度范围 | 通信需求 | 参考来源
```

## 模块 4：通信切换机制参数调研

对应参数：

```matlab
TTT
```

重点调研：

- 3GPP 中 Time-To-Trigger 的标准配置范围
- LTE/5G A3 事件切换中的 TTT 常用取值
- UAV 高速移动场景下 TTT 对切换延迟、乒乓切换和覆盖中断的影响
- UAV handover 仿真论文中的 TTT 设置

注意事项：

- 需要确认代码中 `TTT` 的单位和实现含义，是秒、采样步长，还是抽象时间单位
- 调研结果要和代码单位做映射，避免直接搬用标准值导致量纲不一致

建议输出表：

```text
网络类型 | TTT 标准/论文取值 | 场景 | 影响 | 参考来源
```

## 模块 6：参数耦合关系分析

不能只孤立调研单个参数，还需要分析它们之间的耦合。

重点关系：

- 高度越高，LoS 可能更好，但路径损耗和覆盖结构也可能变化
- 速度越高，切换更频繁，TTT 的影响更明显
- 基站密度越高，覆盖可能增强，但切换次数也可能增加
- TTT 越大，切换更保守，可能减少乒乓切换，但可能增加滞后风险
- 高度范围越宽，优化空间更大，但约束和路径复杂度也增加

建议输出表：

```text
参数 A | 参数 B | 耦合影响 | 是否需要联合实验 | 参考来源
```

## 模块 7：实验参数设计

调研结束后再设计实验值。建议分两类。

第一类：单因素对比。

每次只改变一个参数，用于分析趋势：

- `bsPerKm2`
- `velocity`
- `TTT`
- `altitudeCenter / altitudeBounds`

第二类：场景组合对比。

构造若干现实/典型场景，每个场景绑定一组参数：

```text
场景 | bsPerKm2 | velocity | TTT | altitudeCenter | altitudeBounds | 依据
```

候选场景可以包括：

- 郊区巡检
- 普通城区巡航
- 核心城区巡航
- 高密度园区巡检
- 应急快速巡航

## 推荐调研顺序

1. 场景背景：先确定真实无人机巡航/低空应用场景
2. 高度：明确低空飞行和城市安全约束
3. 速度：确定 UAV 运动模型合理范围
4. 基站密度：确定通信环境稀疏/密集程度
5. TTT：确定通信切换机制配置
6. 参数耦合：分析哪些参数应联合讨论
7. 实验设计：给出最终推荐取值和理由
