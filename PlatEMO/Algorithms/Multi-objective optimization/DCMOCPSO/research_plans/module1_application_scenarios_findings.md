# 模块 1：无人机巡航/低空应用场景背景调研记录

调研日期：2026-06-08

## 调研范围

本模块只调研真实或典型应用场景背景，不直接确定 `bsPerKm2`、`velocity`、`TTT`、`altitudeCenter`、`altitudeBounds` 的实验取值。

重点关注：

- 城市低空巡检
- 交通/轨道/道路巡检
- 城市综合治理
- 物流配送与医疗配送
- 应急响应
- 低空通信与蜂窝联网无人机场景

## 初步结论

现有政府文件、城市案例和学术文献均表明，无人机巡航/低空应用不是单一场景，而是覆盖多类城市与行业任务。后续参数设计不宜只做任意单因素枚举，应优先区分场景类型，再映射参数。

建议将后续实验场景至少划分为：

1. 普通城市综合治理巡航
2. 高密度城区交通/道路巡检
3. 轨道交通或铁路沿线巡检
4. 园区/物流/医疗配送场景
5. 应急响应与公共安全场景
6. 蜂窝联网无人机通信保障场景

## 推荐用于后续参数设计的场景分层

### 1. 城市综合治理巡航

代表来源：

- 上海奉贤政务/警务/民用无人机“一张网”
- 北京延庆城乡综合治理
- 深圳 AI+低空经济道路巡查

场景特征：

- 路径通常覆盖城市街区、重点区域或网格化责任区
- 任务包括巡查、取证、应急发现、视频回传
- 通信需求偏实时，覆盖连续性重要

后续重点参数：

- `bsPerKm2`
- `velocity`
- `TTT`
- `altitudeCenter / altitudeBounds`

### 2. 交通/道路/轨道巡检

代表来源：

- 深圳地铁轨道列车巡检
- 交通运输低空应用典型案例
- 铁路巡检学术文献

场景特征：

- 路径多沿线状基础设施展开
- 巡检任务相对固定，可设定预设路径
- 轨道、高速路等场景对稳定通信和定位连续性要求高

后续重点参数：

- `velocity`
- `TTT`
- `altitudeCenter`
- `bsPerKm2`

### 3. 园区/物流/医疗配送

代表来源：

- 深圳龙岗即时配送、物流、医疗配送
- 上海低空经济行动方案中的低空物流
- 北京延庆农产品空中运输、支线物流配送

场景特征：

- 路径往往连接固定起降点
- 速度和航线效率更重要
- 可能经过城市、园区或郊区混合区域

后续重点参数：

- `velocity`
- `altitudeCenter / altitudeBounds`
- `bsPerKm2`

### 4. 应急响应与公共安全

代表来源：

- 上海奉贤警用无人机快速响应
- 上海低空经济行动方案中的应急救援
- 交通运输典型案例中的水上救援

场景特征：

- 任务具有突发性
- 可能需要更高速度、更低时延、更可靠链路
- 通信中断风险需要重点考虑

后续重点参数：

- `velocity`
- `TTT`
- `bsPerKm2`

### 5. 蜂窝联网无人机通信场景

代表来源：

- Cellular-connected UAV 综述
- UAV handover 与蜂窝通信相关论文

场景特征：

- 无人机作为空中 UE 接入地面蜂窝基站
- 高度、速度和基站密度共同影响覆盖、干扰和切换
- 适合作为本文通信目标函数建模的理论支撑背景

后续重点参数：

- `bsPerKm2`
- `velocity`
- `TTT`
- `altitudeCenter`

## 后续模块衔接

模块 2 高度调研需要区分：

- 城市治理巡航高度
- 轨道/道路巡检高度
- 物流配送高度
- 应急场景高度
- 蜂窝联网 UAV 论文仿真高度

模块 3 速度调研需要区分：

- 多旋翼巡检速度
- 沿线巡检速度
- 配送/应急速度
- 蜂窝联网 UAV 仿真速度

模块 4 TTT 调研需要重点对接：

- LTE/5G A3 handover 标准取值
- 高速移动 UAV 的切换延迟和乒乓切换问题

模块 5 基站密度调研需要区分：

- 郊区/城乡综合治理
- 普通城区
- 城市核心区
- 园区或交通枢纽
- 超密集网络
